### **Phase 2: Fixed AXI SmartConnect Routing**

**Problem Identified:**
The HLS IP's master AXI ports (`m_axi_gmem0`, `m_axi_gmem1`) were connected to the SmartConnect, but the SmartConnect had no path to DDR memory. The address mapping showed:
```
/processing_system7_0/M_AXI_GP0 → 0x40000000 (peripherals only)
```
But we needed access to:
```
DDR Memory → 0x00000000 to 0x1FFFFFFF (512MB)
```

**Solution Implemented:**
1. **Enabled S_AXI_HP0** in the Zynq Processing System configuration
   - This is the High Performance Slave port that can access the full DDR address space
   - M_AXI_GP0 can only access addresses starting at 0x40000000

2. **Added third master port to SmartConnect:**
   - Changed "Number of Master Interfaces" from 2 to 3
   - This created `M02_AXI` port

3. **Connected M02_AXI to S_AXI_HP0:**
   - Wired `axi_smc M02_AXI` → `processing_system7_0 S_AXI_HP0`
   - Ran Connection Automation to wire clocks and resets

4. **Updated address mapping:**
   - Remapped `S01_AXI` and `S02_AXI` (from HLS IP) to use `M02_AXI`
   - Address space now correctly pointed to `0x00000000 [512M]`

**Result:**
- FPGA can now successfully read from DDR memory
- Execution time remained ~253µs (no performance impact)
- But now reading actual data instead of zeros

### **Phase 3: Fixed HLS Data Type Overflow**

**Problem Identified:**
After fixing the AXI routing, results were still wrong:
- Test with values 0-1023: Expected `523776.0`, got `-507.2` or `4305267.0`
- Small value test (0.1 to 1.0): Perfect match ✅
- Medium value test (0 to 99): Perfect match ✅

**Root Cause:**
The HLS code used `ap_fixed<18, 2>` for input samples:
- Only 2 integer bits → can only represent -2.0 to +1.999
- Values like 2.0, 3.0, 1023.0 overflow and wrap around
- This caused incorrect accumulation results

**Solution Implemented:**
Changed data types in `gnss_correlator.cpp`:
```cpp
// OLD (overflow):
typedef ap_fixed<18, 2> sample_t;  // Only 2 integer bits

// NEW (correct):
typedef ap_fixed<32, 16> sample_t;  // 16 integer bits (holds up to 32767)
typedef ap_fixed<64, 24> acc_t;     // 24 integer bits (holds up to 8 million)
```

**Result:**
- Can now handle input values up to 32767 without overflow
- Accumulator can hold sums up to 8 million
- Test with 0-1023: Now returns correct `523776.0` ✅

```python
def generate_gps_prn(prn_id):
    """Generates a 1023-chip GPS L1 C/A Gold Code for PRN ID (1-32)"""
    # G2 tap selections for PRN 1-32 (from GPS ICD-200)
    g2_taps = {
        1: [2,6], 2: [3,7], 3: [4,8], 4: [5,9], 5: [1,9],
        # ... all 32 PRNs
    }
    
    # Generate using G1 and G2 shift registers
    # Output: G1[10] XOR G2[tap1] XOR G2[tap2]
    # Feedback polynomials:
    # G1: x^10 + x^3 + 1
    # G2: x^10 + x^9 + x^8 + x^6 + x^3 + x^2 + 1
```

**Result:**
- Can generate any of the 32 GPS satellite PRN codes
- Each code is 1023 chips long (standard GPS L1 C/A)
