## 🚀 Phase 1: Software Baseline & Profiling
**Objective:** Establish a working software-only GNSS receiver baseline and quantify the computational bottleneck to justify FPGA acceleration.

1. **Signal Generation:** 
   - Utilized `gps-sdr-sim` to generate 30 seconds of simulated GPS L1 C/A baseband data.
   - **Critical Fix:** Resolved a silent acquisition failure caused by a time mismatch. The default simulator used the host system time (2026), but the ephemeris file (`brdc0010.22n`) was from Jan 1, 2022. Added the `-t 2022/01/01,12:00:00` flag to align satellite orbits with the signal generation.
2. **Data Type Resolution:** 
   - Encountered persistent item-size mismatch errors in `gnss-sdr` (e.g., `SignalSource` outputting 8 bytes but `Signal_Conditioner` expecting 1 or 2 bytes).
   - **Solution:** Wrote a Python script to explicitly convert the simulator's default 16-bit interleaved output into a normalized 32-bit float complex (`gr_complex`) file (`gpssim_float.bin`), perfectly matching GNSS-SDR's native expectations.
3. **Profiling Results:** 
   - Successfully acquired and tracked 4 satellites (PRN 08, 10, 15, 16) and decoded NAV subframes.
   - **Metric:** Processed 29.8 seconds of signal data in **2.82 seconds** of CPU time (~10.5x real-time on a high-end x86 laptop). 
   - **Conclusion:** While viable on a desktop CPU, this software-only approach will severely bottleneck on the embedded ARM Cortex-A9 of the Zynq SoC, necessitating hardware acceleration for the correlation math.

## 🚀 Phase 2: HLS Algorithm Extraction & Optimization
**Objective:** Isolate the core DSP math from the GNU Radio framework and synthesize it into efficient FPGA hardware using Vitis HLS.

1. **Core Extraction:** 
   - Extracted the Parallel Code Phase Search (PCPS) complex multiply-accumulate (MAC) logic into a standalone, HLS-friendly C++ function (`gnss_correlator.cpp`).
   - Developed a C++ testbench that reads the actual `gpssim_float.bin` data to verify mathematical correctness against the software baseline.
2. **The Floating-Point Bottleneck (Critical Discovery):** 
   - Initial synthesis with 32-bit `float` math triggered severe timing warnings: `WARNING: [HLS 200-886] Cannot meet target clock period in 'fadd' operation... (combination delay: 22.578 ns)`.
   - The tool was forced to stretch the Initiation Interval (II) to 2 and estimated an Fmax of only ~21.39 MHz, failing the 10ns/25ns target.
3. **The "Pro VLSI" Optimization:** 
   - Replaced 32-bit floating-point arithmetic with Xilinx arbitrary-precision fixed-point math (`ap_fixed<18, 2>`). This perfectly matches the dynamic range of normalized GNSS signals while mapping to ultra-fast, tiny hardware adders.
   - **Result:** The `fadd` delay dropped from ~22.5 ns to < 2 ns.
4. **AXI Interface Integration:** 
   - Added `#pragma HLS INTERFACE` directives to make the core system-ready:
     - `m_axi` (AXI4 Master) for high-bandwidth DDR streaming of `signal_I/Q` and `code_I/Q`.
     - `s_axilite` (AXI4-Lite) for ARM CPU control registers (`num_samples`, `corr_I`, `corr_Q`, `ap_start`, `ap_done`).

## 🚀 Phase 3: Full Vivado Implementation (Post-Synthesis)
**Objective:** Move beyond HLS estimation and run a full, sign-off quality Vivado Implementation (Synthesis, Optimization, Placement, and Routing) to guarantee the design is physically viable.

1. **Execution:** 
   - Utilized the modern Vitis Unified IDE command-line flow: `vitis-run --mode hls --impl --config ...`
   - This automatically spun up Vivado in the background to perform out-of-context synthesis, logic optimization, placement, and routing on the generated RTL.
2. **Final Implementation Metrics (The "Smoking Gun"):**
   - **Target Clock:** 10.000 ns (100 MHz)
   - **Achieved Clock Period:** **6.880 ns (~145 MHz)** 
   - **Worst Negative Slack (WNS):** +3.119 ns (Timing comfortably met)
   - **Unrouted Nets:** **0** (100% successfully routed)
   - **Resource Utilization:** 
     - **DSP48E:** 4 (out of 220) → *Proves efficient mapping of complex MAC to dedicated hardware multipliers.*
     - **BRAM:** 2 (out of 280)
     - **LUT:** 2,501 (4.70% of available)
