**Why we did this:** HLS provides *estimated* timing and resources. Running `--impl` spins up the actual Vivado engine to give us **sign-off quality, physically routed metrics**, proving the design will actually work on silicon.

### 🔍 **Phase 2: Hardware Bring-Up & Debugging**
**Action:** Attempted to boot the physical ZedBoard and validate the HLS IP using various pre-built Linux images (PYNQ-Z1, PetaLinux 2021.2, and Kuiper Linux).  
**The Critical Discovery:** When attempting to test the IP using `devmem 0x43C00000`, the system threw a **"Bus error" (Unhandled fault: external abort on non-linefetch)**.

**Explanation of the "Bus Error":**  
In Zynq SoCs, a "Bus error" when reading a specific memory address (like `0x43C00000`) almost always means **the FPGA fabric is blank**. The Linux kernel tried to read from an AXI-Lite peripheral that physically does not exist yet because the First Stage Boot Loader (FSBL) did not load your `system_wrapper.bit` into the Programmable Logic (PL). The pre-built images we tried contained default or empty bitstreams, not your custom GNSS correlator.

---

### 🔄 **Phase 3: Strategic Pivot & Architecture Decision**
**Action:** Evaluated the root cause of the boot/loading failures and made a strategic decision on how to proceed.  
**The Problem:** The PetaLinux 2021.2 image that successfully booted had a 4-year version gap with your Vitis 2025.2 tools, risking device tree and driver incompatibilities. Furthermore, generic PYNQ-Z1 images failed due to ZedBoard-specific hardware layout mismatches.

**The Decision:** Instead of fighting incompatible pre-built images, we decided to **build a custom Linux image** (either Kuiper Linux or a custom PYNQ build) tailored specifically for this project. 

**Required Features for the Custom Image:**
1. **Matching Toolchain:** Linux Kernel 5.15+ to perfectly match Vitis 2025.2.
2. **FPGA Manager:** Enabled in the kernel to allow dynamic bitstream loading via `fpgautil` or sysfs.
3. **Contiguous Memory Allocator (CMA):** Reserved (e.g., 256MB) in the device tree to allow Python/PYNQ to allocate large, physically contiguous buffers for DMA.
4. **Development Stack:** Python 3, `numpy`, `devmem2`, and SSH access for rapid iteration.
5. **Custom Device Tree Overlay:** To explicitly map your HLS IP to `0x43C00000` (or the address assigned in Vivado), ensuring the Linux kernel knows that memory region belongs to your hardware.
